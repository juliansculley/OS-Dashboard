<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user textarea/path input -> spawn stdin | New untrusted input crosses into a child process via stdin. This is the primary new attack surface in Phase 5. |
| skill name -> spawn/execFile args | The skill identifier becomes a process argument. SEC-03 governs this boundary. |
| skill stdout -> parseOutputPath -> openLinkText | The parsed output path is passed to an Obsidian API. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-07 | Tampering / Information Disclosure | parsed outputPath -> openLinkText | mitigate | A module-scope traversal guard rejects any parsed path whose `\\`/`/`-split segments include `..` BEFORE the path is stored in context or passed to openLinkText (Task 2 acceptance). openLinkText itself performs no filesystem write and no shell exec — it resolves a vault link — so the residual blast radius is limited to opening an unexpected vault note. Combined with 05-01's vault-relative-only contract, this closes the path-traversal concern. |
| T-05-08 | Tampering (command injection via skill name) | spawn/execFile args | mitigate | SEC-03 preserved: the runtime guard `ALLOWED_SKILLS.includes(skill)` is the second statement of the run handler, before any spawn/execFile call (Task 2 acceptance asserts source order). The skill arg is the validated allowlist literal; `spawn`/`execFile` are used WITHOUT `shell: true`, so args are passed as an argv array, never interpreted by a shell. |
| T-05-09 | Tampering (injection via stdin content) | spawn child.stdin | mitigate | Textarea/path content is written to `child.stdin` as a UTF-8 data stream, NEVER concatenated into the args array. Because spawn is invoked without `shell: true`, stdin bytes are delivered to the process as data and cannot be reinterpreted as shell commands. Task 2 acceptance asserts input flows through stdin only. |
| T-05-10 | Denial of Service | spawn never closes / hung skill | accept | A hung `claude` process leaves the button in `loading` (re-click guarded as no-op). No auto-reset fires until `close`, but this only affects one skill's UI state, not the plugin. Manual plugin reload recovers. Acceptable for a single-user local desktop plugin; a kill-timeout is deferred (not required for ASVS L1, no untrusted multi-tenant exposure). |
| T-05-11 | Information Disclosure | stderr captured into Error message | accept | On non-zero exit, stderr (sliced) is wrapped in an Error used only to drive the `error` UI state; it is not rendered to the user verbatim in this phase (UI-SPEC: error state shows only `Failed`). No sensitive stderr is surfaced in the DOM. |
| T-05-SC | Tampering | npm/pip/cargo installs | n/a | No package installs in this phase (zero new dependencies — RESEARCH §"No Package Legitimacy Audit Required"). No legitimacy checkpoint needed. |

No unmitigated HIGH-severity threats. The three new HIGH-surface items (stdin injection T-05-09, skill-name injection T-05-08, path traversal T-05-07) each have a concrete, acceptance-asserted mitigation: spawn-without-shell + stdin-only data, SEC-03 guard order, and the `..` traversal guard.

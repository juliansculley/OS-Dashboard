# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5: Skill Output + UX Polish.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> This phase adds three UI surfaces to the existing Obsidian plugin dashboard:
> 1. Expandable input panel below each input-required skill button (braindump, humanizer)
> 2. Inline output vault link inside the panel after successful skill execution
> 3. Persistent slim status bar between sidebar and page content, visible on all pages
>
> **Contract rule:** All visuals use the existing `--cos-*` CSS token system defined in
> `styles.css`. No new design tokens are introduced. No shadcn or third-party component
> registry. No new npm packages.

## Surface Inventory: New Components

### 1. SkillInputPanel (expandable panel below skill button)

**Trigger:** Clicking a skill button when it is in `idle` state and the skill is `input-required`
(braindump or humanizer). A second click on the button collapses the panel and clears input.

**Panel anatomy:**

| Sub-element | Class | Visual spec |
|-------------|-------|-------------|
| Panel wrapper | `.claudeos-input-panel` | `background: var(--cos-surface)`, `border: 1px solid var(--cos-border)`, `border-radius: var(--cos-radius)`, `padding: var(--cos-space-md)`, `margin-top: var(--cos-space-sm)` |
| Field label | `.claudeos-input-panel__label` | 12px / 600 / `color: var(--cos-muted)` / `text-transform: uppercase` / `letter-spacing: 0.06em` — matches `.claudeos-tile__label` pattern |
| Textarea | `.claudeos-input-panel__textarea` | 14px / 400 / `font-family: var(--cos-font-display)` / `width: 100%` / `min-height: 80px` / `resize: vertical` / `border: 1px solid var(--cos-border)` / `border-radius: var(--cos-radius)` / `padding: var(--cos-space-sm)` / `background: var(--cos-bg)` / `color: var(--cos-text)` |
| Path field (humanizer only) | `.claudeos-input-panel__path` | Same visual spec as textarea, `min-height` unset (single line), `height: 36px` |
| Run button | `.claudeos-run-btn` | Inherits `.claudeos-skill-btn--idle` visual: `background: var(--cos-accent)`, `color: #ffffff`, `padding: var(--cos-space-sm) var(--cos-space-md)`, `border-radius: var(--cos-radius)`, 14px / 600. Disabled when both textarea and path field are empty. |
| Panel gap | — | `gap: var(--cos-space-sm)` between label, field, and Run button (flex column layout) |

**Expanded skill button label states:**

| Skill state | Button label text | Button visual class |
|-------------|-------------------|---------------------|
| idle, panel closed | Original label (e.g. "Braindump") | `.claudeos-skill-btn--idle` (accent fill) |
| idle, panel open | "Cancel" | `.claudeos-skill-btn--idle` but `background: var(--cos-surface-2)`, `color: var(--cos-text)`, `border: 1px solid var(--cos-border)` — muted to signal cancellable state |
| loading | Spinner (Lucide `loader-2` icon) | `.claudeos-skill-btn--loading` (80% accent opacity, cursor not-allowed) |
| success | Check icon + "Done" | `.claudeos-skill-btn--success` (success tint + border) |
| error | X icon + "Failed" | `.claudeos-skill-btn--error` (error tint + border) |

**Panel open/close behavior:**
- Panel opens below its parent skill button with no animation (consistent with project's
  animation-free approach — no existing CSS transitions on layout changes).
- CSS: toggle `.claudeos-input-panel--hidden` which sets `display: none`. Not `height: 0`
  (avoids transition complexity; this phase has no animated expand precedent).
- Input is cleared on collapse (React controlled state reset on toggle).
- Panel collapses automatically when skill transitions to `loading` state (Run clicked).
  After `success` or `error`, panel stays collapsed; output link appears in its place.

**humanizer dual-input precedence rule (CONTEXT.md Specifics):**
- Path field takes precedence when non-empty. Textarea content is silently ignored.
- No mutual exclusivity — both fields remain editable. The precedence rule is implemented
  in `buildHumanizerInput()` at execution time, not in the UI onChange handlers.
- Visual indicator: path field carries placeholder text `"e.g. braindumps/note.md (takes precedence)"`.

### 2. Output Link (inline, inside or below input panel)

**Trigger:** Skill transitions to `success` state AND `outputPath` is non-null (parsed from stdout
via `/^Output:\s+(.+)$/m` regex).

**Placement:** Replaces or sits below the panel area. The panel itself is collapsed on `loading`;
on `success`, the output link renders directly below the skill button in place of the panel.

| Sub-element | Class | Visual spec |
|-------------|-------|-------------|
| Output link wrapper | `.claudeos-output-link` | `display: flex`, `align-items: center`, `gap: var(--cos-space-xs)`, `margin-top: var(--cos-space-sm)` |
| Link icon | Obsidian `setIcon()` using `external-link` | 14px slot, `color: var(--cos-accent)` |
| Link text | `.claudeos-output-link__text` | 14px / 600 / `color: var(--cos-accent)` / `cursor: pointer` / `text-decoration: underline` on hover |

**Interaction:** Click calls `app.workspace.openLinkText(outputPath, '', 'tab')`.
Opens the output note in a new Obsidian tab. No in-dashboard preview.

**No output path case:** When `outputPath === null` after success (e.g. wiki-optimizer before
skill-side `Output:` line is added), the success state renders the button as `Done` with no link.
No error is surfaced — graceful degradation.

**Auto-reset:** After the existing 3-second timer, skill returns to `idle` and the output link
disappears. The link is only transiently visible during the success window — it is not persisted
after reset.

### 3. SkillStatusBar (persistent, App.tsx shell)

**Placement:** Between `<Sidebar />` and `<main className="claudeos-main">` inside a new
`.claudeos-content-wrapper` div. The wrapper uses `flex: 1; display: flex; flex-direction: column`
to stack the status bar above the main content area without disrupting the sidebar-left layout.

**Visibility rule:** Component is always mounted (prevents mount-time layout shift). Hidden
via `display: none` when no skills are active. Shown when `≥1 skill` has `status !== 'idle'`.

| Sub-element | Class | Visual spec |
|-------------|-------|-------------|
| Bar wrapper | `.claudeos-status-bar` | `display: none` (default) |
| Bar wrapper (active) | `.claudeos-status-bar--active` | `display: flex`, `align-items: center`, `gap: var(--cos-space-xs)`, `padding: var(--cos-space-xs) var(--cos-space-md)`, `background: var(--cos-surface)`, `border-bottom: 1px solid var(--cos-border)`, `font-size: 14px` |
| Status text | `.claudeos-status-bar__text` | 14px / 400 / `color: var(--cos-muted)` for running state; `color: var(--cos-success)` for done; `color: var(--cos-error)` for failed |
| Output link in bar | `.claudeos-status-bar__link` | 14px / 600 / `color: var(--cos-accent)` / `cursor: pointer` / underline on hover |

**Text format (D-12):**

| Skill state | Status bar text |
|-------------|----------------|
| loading | `[SkillName] running...` — e.g. `Braindump running...` |
| success + outputPath | `Braindump — Done  Open output` (link on "Open output") |
| success + no outputPath | `Braindump — Done` |
| error | `Braindump — Failed` |

**Multiple simultaneous skills:** Show the first active skill found in `Object.entries(skillStates)`
order. No multi-skill aggregation in this phase.

**Auto-dismiss:** Status bar returns to `display: none` when the active skill's auto-reset timer
fires (3s for success, 5s for error) and all skills return to `idle`.

**Height budget:** Bar is a single line of text (14px) with 4px vertical padding top + bottom.
Total bar height when active: approximately 28px. This height is absorbed from the flex column
in `.claudeos-content-wrapper`; `<main>` must use `flex: 1; min-height: 0; overflow-y: auto`
to prevent vertical overflow when the bar appears.

## State Machine Extension

The existing 4-state machine (`idle | loading | success | error`) is extended to carry
`outputPath`. No new states are added — the machine shape is identical, the payload grows.

```
                      click (input-required skill)
idle ──────────────────────────────────────────────> expanded (local UI state)
                                                          │
                              click "Run" (or click button again to cancel)
                              │                           │
                              ▼                           ▼
                           loading ◄──────────────── idle (panel cleared)
                              │
             ┌────────────────┴────────────────┐
             ▼                                 ▼
          success                            error
     (outputPath | null)               (outputPath: null)
             │                                 │
         3s timer                          5s timer
             │                                 │
             └────────────────┬────────────────┘
                              ▼
                            idle
```

**"expanded" is a local UI state** on `SkillButton` / `SkillInputPanel` — not part of `SkillRunState`
in `AppContext`. Only `loading | success | error | idle` propagate to context and the status bar.

## Security Contract

SEC-03 must be preserved through all refactoring in this phase.

| Rule | Enforcement |
|------|-------------|
| Runtime allowlist check is the first operation in `handleRun` | Before any `spawn()` call: `if (!ALLOWED_SKILLS.includes(skill)) return` |
| Textarea/path field content passes as stdin data only | `child.stdin.write(input, 'utf8')` — never concatenated into command arguments |
| `spawn('claude', ['-p', skill])` uses validated `AllowedSkill`, never raw user string | TypeScript type + runtime guard both enforce this |
| Parsed `outputPath` used only in Obsidian `openLinkText` API | Not written to filesystem; no shell access |

<objective>
Build the cross-page persistence foundation (OUT-02): lift skill run state into a context-backed map that lives above the page-swap boundary, and add an always-mounted persistent status bar in the App shell that is zero-height when idle and shows the running/done/failed state of the active skill on every page.

This plan is the shell layer. It does NOT touch SkillButton, SkillInputPanel, or the spawn/execFile execution logic — that is 05-03. This plan only: (1) defines the new types, (2) extends AppContext, (3) wires the state in App.tsx and mounts the status bar, (4) creates the SkillStatusBar component, (5) adds the status-bar + content-wrapper CSS.

Purpose: OUT-02 requires the running/complete/error status to survive page navigation. Component-local useState in SkillButton (current Phase 2 behavior) is destroyed when the Home page unmounts on navigation. Lifting to App-level state (above the PageComponent swap) and surfacing it in a shell-level status bar is the fix.

Output: New types in types.ts, extended AppContext, an App.tsx that owns the skillStates map and renders the status bar inside a flex content-wrapper, a new SkillStatusBar.tsx, and CSS for the bar.

CRITICAL ARCHITECTURE NOTE — Provider location (verified from source): The `AppContext.Provider` currently lives in `src/views/DashboardView.tsx` (NOT in App.tsx), with value `{ app: this.app, plugin: this.plugin }`. `App.tsx` is rendered INSIDE that provider and does not receive `app`/`plugin` as props. RESEARCH/PATTERNS show wiring "in App.tsx" — the state DOES belong in App.tsx (App persists across page navigation; only PageComponent swaps), but App.tsx must read `app` and `plugin` from the OUTER context via `useAppContext()` and render a NESTED `AppContext.Provider` whose value merges those with the new `skillStates`/`setSkillState`. Do NOT try to read `this.plugin`/`this.app` in App.tsx (they are not in scope there). See Task 2 for the exact pattern. (Alternative: extend the provider in DashboardView.tsx, but then state would live in the view class outside React's render cycle — the nested-provider-in-App approach keeps state in React where the auto-reset timers and re-renders work correctly.)
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| context skillStates -> SkillStatusBar render | The status bar reads skill state (including outputPath) from context and renders text + an openLinkText link. |
| parsed outputPath -> openLinkText | The status bar's Open output link passes outputPath to Obsidian's openLinkText. The path originates from skill stdout (parsed in 05-03). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04 | Information Disclosure | SkillStatusBar Open output link | accept (mitigated upstream/downstream) | outputPath is consumed only by openLinkText (Obsidian API — no filesystem write, no shell). The path is produced by a hardcoded-allowlist skill (05-01 emits vault-relative paths; 05-03 parses and applies a `..` traversal guard before this value enters context). The status bar does not re-derive or concatenate the path; it passes it through verbatim. LOW risk. |
| T-05-05 | Tampering | rendered status text (skillName) | accept | skillName is an Object key from skillStates, which is only ever written by SkillButton (05-03) using a value from the hardcoded ALLOWED_SKILLS array. No untrusted external input reaches the status text. React escapes text content by default (no dangerouslySetInnerHTML used). LOW risk. |
| T-05-06 | Denial of Service | re-render storm on context updates | accept | setSkillState updates context on state TRANSITIONS only (loading/success/error/idle), not per stdout chunk (the chunk accumulation lives in 05-03). Consumer count is small (3 buttons + 1 bar). setSkillState is useCallback-stable. No render storm. |
| T-05-SC | Tampering | npm/pip/cargo installs | n/a | No package installs (zero new dependencies — RESEARCH §Standard Stack). |

No HIGH-severity threats. The only cross-boundary value (outputPath) is hardened by the 05-01 vault-relative contract and the 05-03 traversal guard; the status bar is a pass-through renderer with React's default escaping.

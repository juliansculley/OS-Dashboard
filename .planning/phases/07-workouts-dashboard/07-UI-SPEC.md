# Phase 7 — UI Design Contract

> Visual and interaction contract for Phase 7: Workouts Dashboard.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> This phase adds one new page (`workouts`) to the existing Obsidian plugin dashboard with four
> sub-sections rendered as in-page tabs: Muscle Volume, Exercise Progression, Session History,
> and a Context strip. All data is read from four local JSON snapshots written by
> `notion-workouts-sync.mjs`. The plugin makes zero API calls. Chart.js is the only new
> dependency, bundled via esbuild.
>
> **Contract rule:** All visuals use the existing `--cos-*` CSS token system defined in
> `styles.css`. Minimal new tokens are introduced. No shadcn, no third-party component
> registry. One new npm dependency: `chart.js`.

## Layout: Workouts Page Structure

### Decision: Tabbed layout (not stacked panels)

**Rationale:** Four sections with significant visual depth (two charts, a table with filters,
a context card). Stacking them would require extensive vertical scrolling with no sense of
hierarchy between sections. Tabs give each section full vertical ownership, keep the page
scannable, and match established UX patterns for dashboards with distinct data views.
The tab bar stays visible while section content scrolls, so users can jump between views
without losing the navigation context.

### Page-level layout

```
┌──────────────────────────────────────────────────────────┐
│ Workouts                                (22px display)   │
├──────────────────────────────────────────────────────────┤
│  [Refresh]   Last synced 14:32          (top control bar)│
├──────────────────────────────────────────────────────────┤
│  [Muscle Volume] [Progression] [History] [Context]       │
│  ──────────────────────────────────────────── tab bar    │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  <active tab content>                                    │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

- Page wrapper: `.claudeos-page.claudeos-page--workouts`, flex column, gap `var(--cos-space-lg, 24px)`
- Page title: `<h1 class="claudeos-page-title">Workouts</h1>` — 22px/600, `margin: 0 0 var(--cos-space-md, 16px) 0`
- Refresh bar: `.claudeos-refresh-bar` — same pattern as ProjectsPage: `<RefreshButton />` + "Last synced HH:mm" span — runs `notion-workouts-sync.mjs` (not `notion-sync.mjs`)

## Interaction Contract

### Tab switching

| Trigger | Behavior |
|---------|----------|
| Click tab button | `setActiveTab(tabId)` — instant React state update, no animation, no re-fetch |
| Tab switch | Previous tab unmounts (simplest approach); new tab mounts and reads from already-loaded snapshot state. Snapshots are loaded once on page mount and on refreshNonce change — not per-tab. |

Tab state is local to `WorkoutsPage` — not persisted across page navigation (navigation away
and back resets to `muscle-volume`).

### Refresh button

Identical state machine to `RefreshButton.tsx`:
- `idle` → Refresh icon + "Refresh" label, accent fill
- `loading` → spinner animation, accent 80% opacity, `disabled`
- `success` → check icon + "Synced", green tint, auto-reset 3s
- `error` → X icon + "Failed", red tint, auto-reset 5s

On success: calls `triggerRefresh()` from AppContext (bumps `refreshNonce`). `WorkoutsPage`
`useEffect` hooks on `refreshNonce` re-read all four snapshot files.

### Window preset buttons

Clicking a preset button updates local `windowDays` state:
- `7d` → 7
- `14d` → 14
- `28d` → 28
- `This Meso` → compute from `current_meso.start` to today; disable if no current meso

Local re-aggregation: filter `MuscleVolumeSnapshot.weekly` cells where the ISO week falls
within the selected window. No API call. Re-renders both bar chart and trend line chart.

### Attribution toggle

Clicking `Primary only` sets `attributionMode: 'primary'`; clicking `Primary + Secondary` sets
`attributionMode: 'both'`. Local re-aggregation from the same snapshot data:
- `primary`: sum only `weekly` cells where muscle is in the exercise's `primary[]` list
- `both`: sum all cells (default — matches snapshot's precomputed values since secondary_weight = 1.0)

Because the snapshot is pre-aggregated with secondary_weight = 1.0, "Primary only" must
re-aggregate from `MuscleVolumeSnapshot.by_session` (or the script must emit two sets of weekly
cells). Specification for planner: **emit both `weekly_primary_only` and `weekly_with_secondary`
arrays** from the sync script so the toggle is a simple array swap, not a client-side
re-aggregation of per-line data.

### Exercise select (Progression tab)

Selecting an exercise from the `<select>` updates local `selectedExerciseId` state, which
re-renders the chart and PR tiles for that exercise's `ExerciseSeries`. No API call.

### Session history filters (History tab)

All filters are additive (AND across filter types, OR within multi-select button groups).
Filter state is local to `HistoryTab`. Filtering is synchronous — no debounce needed (session
list is small).

## Chart.js Integration Notes

Chart.js must be imported as an ESM module and bundled by esbuild. The plugin environment
has no `window.Chart` global — do not use the CDN pattern.

```ts
import {
  Chart,
  BarController, BarElement,
  LineController, LineElement, PointElement,
  CategoryScale, LinearScale,
  Tooltip, Legend,
} from 'chart.js';

// Register only what is used (tree-shaking)
Chart.register(
  BarController, BarElement,
  LineController, LineElement, PointElement,
  CategoryScale, LinearScale,
  Tooltip, Legend,
);
```

**Canvas management:** Create chart in `useEffect` on mount; call `chart.destroy()` in the
cleanup function to prevent memory leaks. Use a `useRef<Chart | null>(null)` to hold the
Chart instance. On data prop changes, call `chart.data = newData; chart.update()` rather
than destroying and re-creating (avoids flicker).

**CSS variable resolution:** Chart.js cannot read CSS custom properties directly. Resolve
chart colors at mount time using:
```ts
const style = getComputedStyle(canvasEl.ownerDocument.documentElement);
const chartColor0 = style.getPropertyValue('--cos-chart-0').trim() || '#7c6af7';
```

Declare `--cos-chart-*` tokens inside `.claudeos-dashboard {}` in `styles.css` (same block
as all other `--cos-*` tokens). This ensures resolution works when the canvas is inside
the `.claudeos-dashboard` wrapper.

**Axis styling:** Pass `color: computedMutedColor` (resolved from `--cos-muted`) to
`Chart.defaults.color` before creating charts so tick labels and legend text inherit the
muted text color. Do this once at `WorkoutsPage` mount, not per chart.

**No global Chart.defaults mutation in plugin scope** — scoped to chart creation only to
avoid affecting other potential Chart.js consumers.

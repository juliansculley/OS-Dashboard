<objective>
Build the standalone Node ESM sync script (`scripts/notion-sync.mjs`) and supporting repo infrastructure. The script reads the Notion integration token from outside the synced vault, queries the Tasks, Projects, and Newsletter Content Hub data sources via the Notion REST API (`2025-09-03`), transforms each response into the compact §5 JSON shape, and writes atomic snapshot files to `.dashboard-data/`. This is the entire data layer of Phase 3 — it can be built and verified with zero plugin changes, which de-risks the rest of the phase.

Purpose: Decouple all network and secret-handling code into a deterministic, dependency-free script (D-01, D-02). The plugin stays a pure display + execFile layer.
Output: `scripts/notion-sync.mjs`, `.gitignore` updated, and (once the user completes the Notion integration setup) three populated snapshot files.
</objective>

    Query helper `queryDataSource(uuid, body)`: `POST` to `${base}${uuid}/query` with headers `Authorization: Bearer ${token}`, `Notion-Version: 2025-09-03`, `Content-Type: application/json`. Body merges the caller's `filter`/`sorts` with `page_size: 100`. Pagination: loop following `start_cursor` from the previous response's `next_cursor` while `has_more` is true, accumulating `results`. If a response is not `ok`, throw an Error including the HTTP status and the response body text.

    Tasks query + transform (D-05, D-07): filter `{"property":"Status","status":{"does_not_equal":"Done"}}` (Status is a `status`-type property — use the `status` operator, NOT `select`), sort `[{"property":"Due","direction":"ascending"}]`. For each page result, build a `TaskItem`: `name` = `props.Name.title[0]?.plain_text ?? ''`; `status` = `props.Status.status?.name`; `priority` = `props.Priority.status?.name` (omit key when undefined); `due` = `props.Due.date?.start` (omit when undefined); `url` = the deep link (see link rule below). OMIT the `project` field entirely (D-06). Compute counts over the FULL active set BEFORE capping: `active_count` = total active items; `overdue_count` = items whose `due` is a date strictly before today (local date, YYYY-MM-DD compare); `due_soon_count` = items whose `due` is on-or-after today AND on-or-before today + `dueSoonDays` (use 3; this mirrors the `dueSoonDays` default Plan 2 adds to settings). Then cap `items` to the first 10 after the ascending-Due sort (D-07).

    Projects query + transform (D-05): filter combining `Status` is any of `["Work Doing","Doing","Ongoing"]` AND `Archived` (checkbox) equals false. Use an `and` filter: one clause `{"property":"Status","status":{"equals":...}}` is single-valued, so use an `or` of three `status.equals` clauses wrapped in the `and` with `{"property":"Archived","checkbox":{"equals":false}}`. For each result build a `ProjectItem`: `name` from `props.Name.title[0]?.plain_text ?? ''`; `status` from `props.Status.status?.name`; `progress` = read `props.Progress` — it is a formula returning a number (the "% of completed tasks" formula); read `props.Progress.formula.number` and round to an integer, omit the key if not a finite number. OMIT `active_tasks` and `overdue_tasks` (the `Meta` formula's string format is undocumented — do not parse it). `url` = deep link. Set `active_count` = items length.

    Newsletter query + transform (D-05, critical findings 1 and 6): the title property is `Title`, NOT `Name` — read `props.Title.title[0]?.plain_text ?? ''`. Fetch ALL items (no server-side status exclusion that risks multi-value gaps) then filter client-side, dropping any item whose `Status.status?.name` is `"10. Published"` or `"11. Deleted"`. For each surviving item build a `NewsletterItem`: `name` from Title; `stage` from `props.Status.status?.name`; `content_type` from `props['Content Type'].select?.name` (omit when undefined); `platform` from `props.Platform.select?.name` (omit when undefined); `url` = deep link. Build `by_stage` as an object mapping each present `stage` string to its count (only stages that actually occur).

    Deep link rule (Specific Ideas): `url` = `https://notion.so/` + the page `id` from the result with all dashes removed (`result.id.replace(/-/g, '')`).

    Atomic write (NOTION-03, D-08): determine the output directory. Resolve `.dashboard-data/` relative to the OS-Dashboard repo root — derive the repo root from the script's own location using `path.dirname(fileURLToPath(import.meta.url))` then `path.join(scriptDir, '..', '.dashboard-data')`. Create the directory with `fs.mkdir(dir, { recursive: true })`. For each snapshot: stamp `generated_at: new Date().toISOString()` onto the object, `JSON.stringify(obj, null, 2)`, write to `${finalPath}.tmp`, then `fs.rename(tmpPath, finalPath)`. Write three files: `tasks.json`, `projects.json`, `newsletter.json`.

    Top-level flow: wrap the three query+write operations in a try/catch. On any thrown error, print the error message to stderr and `process.exit(1)`. On full success, print a one-line success summary (counts written) to stdout and let the process exit 0.

Also document that Node 18+ is required and the node path on this machine is C:\Users\scull\AppData\Local\nvm\v20.20.2\node.exe.

    Do NOT hardcode the token anywhere. Do NOT add any npm dependency. Do NOT read any file inside the vault for the token.

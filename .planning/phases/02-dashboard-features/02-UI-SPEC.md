## Typography

Fully inherited from Phase 1. No new sizes or weights.

| Role | Size | Weight | Line Height | Phase 2 Usage |
|------|------|--------|-------------|---------------|
| Body | 14px | 400 (regular) | 1.5 | Skill button labels; Settings input labels; Social Stats metric values; tile values |
| Label | 12px | 600 (semibold) | 1.3 | Tile label text (uppercase, letter-spacing: 0.06em); Skills section heading; Social Stats section headings; Settings section headings; "No data" label in tiles |
| Display | 22px | 600 (semibold) | 1.2 | Page titles (Home, Social Stats, Settings) — inherited from Phase 1 |

**Weight rule (inherited):** Two weights only — 400 and 600. No exceptions.

**Tile value sizing exception:** The numeric value displayed in a status tile (e.g., the count in "Active projects") uses 22px / 600 — the display size — to give it visual hierarchy over the label. The timestamp value in "Last vault sync" uses 14px / 400 because it is a string, not a count.

All color tokens are inherited from Phase 1. Phase 2 adds usage rules for new states (loading, success, error) only.

| Role | Token | Value | Phase 2 Usage |
|------|-------|-------|---------------|
| Dominant (60%) | `var(--cos-bg)` | `var(--background-primary)` | Main canvas, Settings tab background |
| Secondary (30%) | `var(--cos-surface)` | `var(--background-secondary)` | Tile card background; Skills button background (idle); Social Stats card background |
| Surface variant | `var(--cos-surface-2)` | `var(--background-secondary-alt, var(--background-secondary))` | Tile hover; Skill button hover (idle state) |
| Accent (10%) | `var(--cos-accent)` | `#7c6af7` | See reserved list below |
| Accent hover | `var(--cos-accent-hover)` | `#6857e0` | Skill button hover (idle state only) |
| Muted text | `var(--cos-muted)` | `var(--text-muted)` | Tile "No data" label; Social Stats empty state body; Settings help text |
| Faint text | `var(--cos-faint)` | `var(--text-faint)` | Tile dash value (`—`) when no data |
| Destructive | `var(--color-red, #e53e3e)` | `#e53e3e` | Skill button error indicator icon and text |
| Border | `var(--cos-border)` | `var(--background-modifier-border)` | Tile card border; Settings input border |
| Success | `var(--color-green, #38a169)` | `#38a169` | Skill button success indicator icon and text |

**Accent (`#7c6af7`) reserved exclusively for (Phase 2 additions):**
1. Logo / wordmark — inherited from Phase 1
2. Active nav item text and background tint — inherited from Phase 1
3. Skill trigger buttons — background color in idle state (`--cos-accent`), hover (`--cos-accent-hover`)
4. Settings save confirmation text (if any future confirmation is added)

Accent is NOT used on: tile cards, tile labels, tile values, Social Stats metrics, Settings input fields, empty state elements, borders.

**Success color (`#38a169`):** Used only on the skill button post-execution success indicator. Not used anywhere else in Phase 2.

**Error color (`#e53e3e`):** Used only on the skill button post-execution error indicator. Not used anywhere else in Phase 2 (data-missing states use `--cos-muted`, not red — missing data is not an error).

## Interaction Contract

### Status Tiles

| State | Trigger | Visual |
|-------|---------|--------|
| Data state | `value !== null` | Value displayed at correct size/weight (see Typography); label in 12px/600/uppercase/muted |
| No-data state | `value === null` (file missing, path empty, parse error) | Value area shows `—` in `var(--cos-faint)` at 22px/400; label shows in 12px/600/muted; below value, show "No data" in 12px/400/`var(--cos-muted)` |
| Hover | Mouse over tile | Background shifts to `var(--cos-surface-2)`, `transition: background 150ms` |

Tile layout is stable in both states — no layout shift between data and no-data. Both states occupy identical space.

### Skill Buttons

Each button cycles through 4 states. State is local to the button component (not lifted to page level).

| State | Trigger | Visual | Duration |
|-------|---------|--------|----------|
| Idle | Default | Background `var(--cos-accent)`, text white, label text, no icon | — |
| Idle hover | Mouse over | Background `var(--cos-accent-hover)`, `transition: background 150ms` | — |
| Loading | Click | Background `var(--cos-accent)` at 80% opacity, loading spinner (16px, white, Lucide `loader-2` icon with CSS rotation animation), label hidden | Until child_process exits |
| Success | Exit code 0 | Background `var(--color-green, #38a169)` at 15% opacity, border `1px solid var(--color-green, #38a169)`, text `var(--color-green, #38a169)`, checkmark icon (Lucide `check`) + "Done" label | Auto-resets to idle after 3 seconds |
| Error | Exit code non-zero | Background `var(--color-red, #e53e3e)` at 15% opacity, border `1px solid var(--color-red, #e53e3e)`, text `var(--color-red, #e53e3e)`, X icon (Lucide `x`) + "Failed" label | Auto-resets to idle after 5 seconds |

Button is not clickable during loading state (`pointer-events: none` OR `disabled` attribute on the element).

**Loading spinner CSS:**
```css
@keyframes cos-spin {
  from { transform: rotate(0deg); }
  to   { transform: rotate(360deg); }
}
.claudeos-skill-btn--loading .cos-spinner {
  animation: cos-spin 0.8s linear infinite;
}
```

**Button sizing:** `padding: 8px 16px` (sm vertical, md horizontal), `border-radius: var(--cos-radius)` (8px), min-width: 100px, font-size: 14px, font-weight: 600.

### Social Stats Page

| State | Trigger | Visual |
|-------|---------|--------|
| Data state | File readable, path set | Metrics displayed per layout spec above |
| Empty state | Path empty OR file missing/unreadable | Full-card empty state (see Copywriting Contract below) |

### Settings Tab

Settings use Obsidian's native `Setting` component via `PluginSettingTab`. Each text input:
- Placeholder: empty string (the field shows Obsidian's default placeholder behavior)
- On change: `plugin.saveData()` called immediately (no explicit save button — Obsidian convention for settings)
- Validation: none at input time — validation occurs when the tile or page attempts to read the file

## Data Schema Contract

Researcher-defined schemas (Claude's Discretion, D-11 and D-09).

### Tile Data Files

**Decision: Each tile has its own JSON file** (not a shared directory). Rationale: different automations/MCPs write to different tiles independently; per-tile paths in settings are clearer for the user.

**Tile 1 — Last vault sync** (`lastSyncPath` setting):
```json
{
  "timestamp": "2026-06-04T14:32:00Z"
}
```
- Field: `timestamp` (ISO 8601 string)
- Display format: `YYYY-MM-DD HH:mm` (local time, formatted from the ISO string)
- If field missing or unparseable: render no-data state

**Tile 2 — Active projects** (`activeProjectsPath` setting):
```json
{
  "count": 7
}
```
- Field: `count` (integer)
- Display format: plain integer string (e.g., `"7"`)
- If field missing or not a number: render no-data state

### LinkedIn Data File (`linkedinDataPath` setting):
```json
{
  "followers": 1240,
  "connections": 892,
  "posts": 48,
  "updated_at": "2026-06-04T00:00:00Z"
}
```
- Fields: `followers` (int), `connections` (int), `posts` (int), `updated_at` (ISO 8601, optional — displayed as "Updated: YYYY-MM-DD" if present)
- All numeric fields displayed as formatted integers (locale string with comma separators)
- If file missing/unreadable: render empty state

### X (Twitter) Data File (`xDataPath` setting):
```json
{
  "followers": 3100,
  "following": 412,
  "tweets": 221,
  "updated_at": "2026-06-04T00:00:00Z"
}
```
- Fields: `followers` (int), `following` (int), `tweets` (int), `updated_at` (ISO 8601, optional)
- All numeric fields displayed as formatted integers
- If file missing/unreadable: render empty state

### TypeScript interfaces (add to `src/types.ts`):
```typescript
export interface TileSyncData {
  timestamp: string; // ISO 8601
}

export interface TileCountData {
  count: number;
}

export interface LinkedInData {
  followers: number;
  connections: number;

  updated_at?: string;
}

export interface XData {
  followers: number;
  following: number;
  tweets: number;
  updated_at?: string;
}

export interface ClaudeOSSettings {
  lastSyncPath: string;       // default: ""
  activeProjectsPath: string; // default: ""
  linkedinDataPath: string;   // default: ""
  xDataPath: string;          // default: ""
}

export const DEFAULT_SETTINGS: ClaudeOSSettings = {
  lastSyncPath: "",
  activeProjectsPath: "",
  linkedinDataPath: "",
  xDataPath: "",
};
```
